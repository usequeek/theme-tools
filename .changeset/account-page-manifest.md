`queek.app.toml` now accepts the shopper account manifest as the server does: an `app_page` block with the `account-page` target and a `url`, and one block with the `account-order` target. The check also refuses a title that is not 1-40 characters of visible text, a second page or account block, a page url that is not https, carries credentials or a fragment, or sits on a Queek domain, and an account block without `extensions.proxy.share_customer_id`, so `queek app deploy` fails locally instead of at the server. A `url` on any other block is still refused as an unknown field. Every url field the check covers now refuses control characters, whitespace, invisible characters and a backslash in the host, accepts an upper-case `HTTPS://` scheme, ignores whitespace around a url and reads an empty optional url as not set (as the server does), and `logo_url`, `developer_url`, `privacy_url` and `support_url` are checked as https urls. Every text value in `queek.app.toml` is now read the way the server reads it: whitespace and invisible characters around it are ignored, an empty optional value counts as not set, and length caps count characters (an emoji is one) after that trim. An empty value for a field that cannot be empty (a list, a table, a true/false setting) is refused with the server's wording. A label made only of no-break or zero-width spaces is refused, as the server does. The check also gains the server's rules for `description`, `developer`, `tagline`, `category`, `highlights`, `pricing`, the `required` flag on settings and inputs, `image` and `when` tables, and the fields of a print layout. It still cannot check what needs the server's own data: the scope and webhook topic catalogues, whether a host resolves, and the demo store.
